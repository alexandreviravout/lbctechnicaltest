# Bugs found in the starter code

| # | Bug in the starter code                                                       | Where | Why it is a problem | Fix | Status |
|---|-------------------------------------------------------------------------------|---|---|---|---|
| 1 | `GlobalScope.launch` to load albums                                           | `AlbumsViewModel` | The coroutine is not tied to any lifecycle: it keeps running after the screen is closed and can leak the ViewModel | Use `viewModelScope`, cancelled when the ViewModel is cleared | ✅ Fixed |
| 2 | Exceptions swallowed with `catch (_: Exception) { /* TODO */ }`               | `AlbumsViewModel` | A network error shows an empty screen, with no message and no way to retry | Errors are returned as `Result` (kotlin-result) and mapped to an `Error` state with a Retry button | ✅ Fixed |
| 3 | `LaunchedEffect(Unit) { viewModel.loadAlbums() }`                             | `AlbumsScreen` | Albums are reloaded from the network on every configuration change (rotation, dark mode…) | Albums are loaded once in the ViewModel `init` | ✅ Fixed |
| 4 | `MutableSharedFlow` without replay to expose albums                           | `AlbumsViewModel` | A value emitted while nothing collects is lost, so the list can stay empty | `StateFlow` with a sealed `UiState` (Loading, Success, Error) | ✅ Fixed |
| 5 | HTTP logging interceptor added when `!BuildConfig.DEBUG`                      | `DataDependencies` (OkHttp) | Full response bodies are logged in **release** builds and never in debug: inverted condition, performance and data exposure issue | Logging interceptor added in debug builds only | ✅ Fixed |
| 6 | `AnalyticsHelper.initialize(this)` stores the Activity in a long-lived object | `MainActivity`, `DetailsActivity`, `AnalyticsHelper` | Memory leak: the destroyed Activity is kept in memory (reported by LeakCanary) | `@Singleton` injected by Hilt with the `@ApplicationContext`, `initialize()` removed | ✅ Fixed |
| 7 | `DetailsActivity` exported with a `MAIN` / `LAUNCHER` intent filter           | `AndroidManifest.xml` | The app shows two icons in the launcher, and the details screen can be opened without an album | `DetailsActivity` removed, details screen implemented as a Compose navigation destination | ✅ Fixed |
| 8 | Details screen is a "work in progress" image                                  | `DetailsActivity` | The details screen required by the assignment does not exist | Details screen with image, title, tags and favorite toggle | ✅ Fixed |
| 9 | Composable `modifier` parameter reused on a child                             | `AlbumItem` (`AsyncImage`) | A modifier passed by the caller is applied twice: to the card and to the thumbnail | Child uses a fresh `Modifier`, the parameter is only applied to the root `Card` | ✅ Fixed |
| 10 | Manual dependency container (`AppDependencies`, `AppDependenciesProvider`)    | `app` | No scoping and manual wiring, hard to test and to extend | Hilt dependency injection | ✅ Fixed |
| 11 | No data persistence                                                           | `data` | No albums without network, nothing kept after restart | Room as single source of truth with offline fallback | ✅ Fixed |
| 12 | `local.properties` committed                                                  | Repository root | Contains a machine-specific SDK path and must not be versioned | Added to `.gitignore` and removed from the index (`git rm --cached local.properties`) | ✅ Fixed |
| 13 | Selection tracking on album click                                             | `MainActivity` → `AnalyticsHelper.trackSelection` | The call was lost when navigation moved to Compose, so selections are no longer tracked | `trackSelection` called when the details screen opens, in `AlbumDetailsViewModel`, and covered by a unit test | ✅ Fixed |
